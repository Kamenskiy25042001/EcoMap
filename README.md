# Эко-карта г. Алтай (ВКО): GitHub Pages + Cloudflare Worker

Сайт статический (GitHub Pages). Заявки и фото сохраняются **в самом репозитории**: `data/reports.json` и `data/photos/*.jpg`.
Токен GitHub не попадает в код сайта: его хранит маленький сервис (Worker), который делает коммиты.

```
Форма на сайте ──POST──> Cloudflare Worker (секрет GITHUB_TOKEN) ──коммит──> репозиторий
Карта ──читает──> data/reports.json и data/photos/ из репозитория
```

## Настройка (один раз)

### 1. Токен GitHub (fine-grained)
GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate:
- Repository access: **Only select repositories** → ваш репозиторий
- Permissions → Repository → **Contents: Read and write**

**Никому не показывайте токен и не вставляйте его в файлы репозитория.** Если он уже где-то засветился, создайте новый, а старый удалите.

### 2. Сайт на GitHub Pages
Публичный репозиторий → загрузить все файлы этой папки (кроме `worker/`, она нужна только для Cloudflare — можно оставить) →
Settings → Pages → *Deploy from a branch* → `main` / root. Адрес: `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`.

### 3. Worker на Cloudflare (бесплатно)
1. dash.cloudflare.com → Workers & Pages → Create → **Create Worker** → Deploy → **Edit code**.
2. Вставьте содержимое `worker/worker.mjs` (заменив весь код) → Deploy.
3. Settings → Variables and Secrets → добавьте:
   | Имя | Тип | Значение |
   |---|---|---|
   | `GITHUB_TOKEN` | **Secret** | ваш токен |
   | `REPO` | Text | `ЛОГИН/РЕПОЗИТОРИЙ` |
   | `BRANCH` | Text | `main` |
   | `ALLOWED_ORIGIN` | Text | `https://ЛОГИН.github.io` (без слеша и пути) |
4. Скопируйте адрес Worker (вида `https://имя.аккаунт.workers.dev`).

### 4. Свяжите сайт и Worker
В `app.js` в начале впишите `API: 'https://имя.аккаунт.workers.dev'` и сохраните (commit). Если сайт открыт не с github.io,
впишите ещё `REPO: 'ЛОГИН/РЕПОЗИТОРИЙ'`.

## Как добавить места вручную (сразу много)
В репозитории есть `data/reports.json` с 15 демонстрационными местами (в описании стоит «Демо:»). Откройте файл на GitHub (карандаш),
удалите демо-блоки и добавьте свои в том же формате:
```
{ "id": "m1", "category": "dump", "address": "ул. Ленина, 10", "description": "Свалка у дома",
  "lat": 49.7312, "lng": 84.2601, "photo": null, "t": 1790000000000 }
```
`category`: `dump`, `air`, `water`, `waste`, `other`. Если `lat`/`lng` не знаете, поставьте `null`: карта сама найдёт координаты по адресу
(медленнее, примерно 1 секунда на адрес при первом открытии). Фото: положите файл в `data/photos/` и укажите `"photo": "data/photos/m1.jpg"`.
Запятые между блоками обязательны, последний блок без запятой. Заявки жителей Worker добавляет в этот же файл.
Демо-места влияют на карту риска (учитываются заявки за 90 дней), поэтому перед реальным использованием их стоит удалить.

## Как пользоваться
- Житель вводит адрес, описание, при желании выбирает фото → заявка и фото коммитятся в репозиторий → через пару секунд маркер на карте.
- **Удаление:** на GitHub откройте `data/reports.json`, удалите нужный блок `{ ... }` и (если было фото) файл `data/photos/<id>.jpg`.
- **Объекты и зоны:** правятся в `data.js` на GitHub (карандаш).
- Каждый коммит перезапускает сборку Pages — это нормально.

## Ограничения (честно)
- Адрес Worker публичный. Проверка `ALLOWED_ORIGIN` и лимит 10 заявок/час на IP защищают от случайного мусора, но не от целенаправленного спама.
  Модерации нет, по вашему желанию: лишнее удаляется правкой файла.
- Репозиторий должен быть публичным: карта читает данные и фото без токена. Не пишите в заявках личные данные.
- Чтение через API GitHub: 60 запросов в час с одного IP. Для демо хватает.
- Фото принимаются только JPEG (сайт сжимает их сам до ~450 КБ).
- Запись идёт одним файлом `reports.json`. При очень частых одновременных заявках Worker повторяет попытку до 4 раз.
